Baseline measures exact predicate only, not mounted UI; inspect actual notification reconciliation and duplicate handling before altering cadence. Recipient notification route selects recipient-scoped ready events, then awaits drain; a stalled drain can delay a durable inbox response. Preserve active/unknown fast cadence, no false successful state.
R09 pickupPush.ts claim→sendable→send→finish, recipient/owner fenced in SQL. Recovered launch SQL uses 30s lease, max5 attempts, bounded10 scan, skip locked, exponential 30s*2^attempts retry, rejects expired/mismatched finish, checks active token and ready status. Existing API awaits provider and RPC; no explicit deadline, so a hanging promise may block response beyond lease; merchant best-effort new order push likewise awaits lookup and allSettled sends (max5), replay does not resend. Existing archived SQL authority remains; synthetic lease model not real SQL acceptance. Provider acceptance != delivery; timeout != proof of no send. Do not blindly mark sent or permanent on ambiguous timeout, do not introduce detached background sends/retry storm or guarantee exactly-once FCM; preserve durable inbox authority and no auto mutation replay. Later disposable real schema lease/fence verification and actual device delivery remain open.
